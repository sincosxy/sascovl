# CargoFlow — контекст для ИИ-ассистента

Сначала прочти [`README.md`](README.md): там устройство проекта, роли, статусы, формат коносамента
и команды запуска. Здесь — правила работы, ловушки, на которые уже наступали, и список незакрытого.

## Правила владельца проекта

- Общение на русском. Сообщения коммитов — на русском.
- Один разработчик, одна ветка `main`. Сервер обновляется через `git pull` этой ветки (`./deploy.sh`).
  Коммит и пуш — только по явной команде («коммит, пуш»).
- Не делать жёстких рамок там, где достаточно предупреждения: некорректный номер контейнера
  сохраняется и подсвечивается красным, несовпадение маршрута заявки и рейса — предупреждение.
  Жёсткие запреты только там, где владелец сказал явно (в рейс — только с номером, пломбой
  и подтверждённым поступлением на терминал).
- Клиенту — простота, оператору — вся мощь правок.
- Минимум новых файлов вёрстки; переиспользовать существующие partials.
- Сервер слабый, на нём много чужих контейнеров: не добавлять тяжёлые зависимости и фоновые сервисы.

## Как здесь устроен фронтенд

- HTMX подменяет `#main-content`. Эндпоинты возвращают HTML-фрагменты, не JSON.
- Два каркаса: `base.html` (клиент, а также страница входа) и `operator/base_ops.html` (оператор/админ).
  `index.html` выбирает каркас по роли.
- Экранирование Jinja включено. Опасные места — HTML, собранный f-строками в Python,
  и значения внутри JS-строк в атрибутах `hx-on:click` / `@click`.

## Ловушки (каждая уже стоила бага)

1. **Наследование атрибутов HTMX.** `hx-target`, `hx-swap` и др. наследуются вложенными элементами.
   Счётчик уведомлений внутри кнопки с `hx-target="main"` вставлял свой ответ на место всей страницы.
   У любого вложенного элемента с собственным `hx-get` ставь `hx-target` явно.
2. **401 возвращает `HX-Redirect: /login`.** Любой автоматический HTMX-запрос на странице без входа
   (`hx-trigger="load"`) зациклит `/login`. `login.html` наследует `base.html`, поэтому всё, что
   в шапке ходит на сервер, должно быть под `{% if user %}`.
3. **Async SQLAlchemy не умеет ленивую загрузку.** Обращение в шаблоне к незагруженной связи
   (`order.shipper`, `container.voyage`) падает с `MissingGreenlet`. Добавил поле в шаблон — добавь
   `selectinload` / `joinedload` во ВСЕ запросы, которые этот шаблон рендерят. Один partial часто
   рендерится из нескольких эндпоинтов:
   - `partials/order_summary.html` — `get_order_summary`, `get_step_4`, `save_step_3`;
   - `partials/order_details_table.html` — `get_order_details` (две ветки: клиент и оператор);
   - `containers/container_row.html` — список, правка, отмена, восстановление;
   - `operator/manage_order.html` — `manage_order`, и его же вызывает `cancel_container`.
   - `partials/arrival_cell.html` — использует только колонки контейнера и глобал `today()`
     (зарегистрирован в окружениях шаблонов `main.py` и `containers_routes.py`).
4. **`autoflush=False` у сессии.** Перед запросом, который должен увидеть несохранённые изменения,
   нужен явный `await db.flush()` (см. `bl.sync_order_status`).
5. **`create_all` при старте не добавляет колонки.** Новое поле в существующей таблице = миграция
   Alembic. Новую таблицу `create_all` может создать раньше миграции, поэтому миграция с
   `create_table` должна проверять `has_table` (пример — `e7b2f4c81d06_add_notifications.py`).
6. **Эндпоинты вызывают друг друга как функции** (`return await manage_order(...)`,
   `await operator_dashboard(...)`). Параметры `Depends(...)` при таком вызове не подставляются —
   передавай `request` и `db` явно.
7. **Номер контейнера проверяется в модели.** `Container._check_container_number` (`@validates`)
   при любом присвоении приводит номер к верхнему регистру и выставляет `valid_number`.
   Не выставляй `valid_number` вручную. Массовый `update(Container).values(container_number=...)`
   проверку обойдёт.
8. **Статус `IN_PROGRESS` / `EXECUTING` не ставь вручную.** После любого изменения `voyage_id` или
   `is_cancelled` у контейнера вызывай `await sync_order_status(db, [order_id])` до `commit`.
   В шаблонах проверяй оба статуса, если речь про «заявка утверждена» (пример — показ PIN-кода).
9. **Сборка образа.** `svglib` закреплён на 2.4.0: версия 1.6.0 тянет `pycairo`, который
   компилируется из исходников полчаса. Не добавляй в `requirements.txt` пакеты без готовых wheel
   и не делай `pip freeze` из локального окружения целиком.
10. **Синхронный `requests` в async-обработчиках** (FESCO, ВМТП в `helpers.py`) блокирует весь
    сервер на время запроса. Новые внешние вызовы делай через `httpx.AsyncClient`.

## Как проверять изменения

PostgreSQL и Docker в среде ассистента обычно недоступны. Рабочий приём — временная SQLite-база:

```bash
pip install --target /tmp/x/lib aiosqlite
DATABASE_URL="sqlite+aiosqlite:////tmp/x/t.db" PYTHONPATH="/tmp/x/lib:." venv/bin/python test.py
```

В скрипте: `Base.metadata.create_all`, засеять данные, `fastapi.testclient.TestClient(app)`,
cookie `access_token = create_access_token({"sub": email})`. Так проверяются права, запросы и
рендер шаблонов. Так **не** проверяются: поведение HTMX в браузере (ловушки 1 и 2), миграции,
специфика PostgreSQL. Об этом надо честно говорить владельцу.

## Где что менять

| Задача | Файлы |
|---|---|
| Правило постановки в рейс, формат коносамента, новый порт/линия | `app/bl.py` (`_PORTS`, `bl_prefix`, `missing_for_voyage`) |
| Новое уведомление клиенту | `bl.notify_owner(db, order, text)` до `commit` |
| Новое уведомление операторам | `await bl.notify_staff(db, order, text)` до `commit` |
| Поступление на терминал | `bl.confirm_arrival` / `cancel_arrival` / `can_confirm_arrival`, блок `partials/arrival_cell.html` (страница заявки оператора и строка списка контейнеров) |
| Новый статус заявки | `bl.py`, `orders_list.html`, `operator/dashboard.html`, `operator/manage_order.html`, `order_details_table.html` |
| Блоки дашборда оператора | `operator/dashboard.html` (группы `new_orders` / `other_orders`) |
| Права доступа | `app/auth.py`; у роутеров `/admin`, `/voyages`, `/containers` стоит `require_staff` |

## Незакрытое

Безопасность (из аудита, не исправлено):
- нет ограничения попыток входа на `/api/login`;
- токен живёт 24 часа и не отзывается при выходе и смене пароля;
- пароль длиннее 72 байт даёт 500 (`bcrypt` 5.0);
- `/docs`, `/openapi.json` и бесполезный `/me` открыты;
- XSS: f-строки в `main.py` (`search_counterparties`, `search_address`, `schedule_view`),
  `admin_routes.py` (`check_demands`), `helpers.render_demands_table`; значения в JS-строках в
  `partials/cp_search_results.html` и `voyages/vessel_search_results.html`;
- оператор может править/удалять компании (везде только `require_staff`);
- ВМТП: `verify=False` и логин/пароль в строке запроса;
- первый админ создаётся с логином и паролем pgAdmin.

Инфраструктура:
- в прод-профиле uvicorn запущен с `--reload` (владелец решил пока оставить);
- порт 8000 опубликован без TLS — зависит от того, есть ли перед ним reverse proxy.

Функциональные хвосты:
- старые заявки и контейнеры не пересчитаны: `valid_number` и статус `EXECUTING` обновятся только
  при следующем изменении;
- одно уведомление на каждый контейнер (при групповом переносе клиент получает много строк);
- ручная правка коносамента и удаление рейса клиента не уведомляют;
- у контейнеров, которые были в рейсах до миграции `f3a9c2d4e5b1`, дата поступления = дата миграции;
- правка пломбы оператором в карточке контейнера не уведомляет и не сбрасывает поступление;
- контейнеры из черновиков видны в списке «Активные» (в рейс не ставятся);
- отменённую клиентом заявку оператор всё ещё может «Обработать»;
- дефисы и пробелы внутри номера контейнера не вычищаются;
- известные баги: `helpers.format_vmtp_date` (неверный вызов `datetime.datetime`), присвоение строки
  связи `pre_carriage_carrier` в `save_step_3`, нет шаблона `containers/containers_page.html`.
